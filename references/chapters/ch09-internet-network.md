# Как работает интернет и сеть

## Главная мысль

«Локально работает» означает только, что клиент и сервер встретились на вашем компьютере. Внешняя доступность — цепочка браузер → DNS → IP → порт → firewall → reverse proxy → приложение → база → ответ. Диагностика должна сужать место сбоя по этой цепочке, а не сразу обвинять код.

## Модели и правила

- **Клиент** отправляет запрос; **сервер** слушает адрес/порт и возвращает ответ.
- **DNS** переводит домен в IP. Домен, IP и сервер — разные сущности, проверяемые отдельно.
- **Порт** — вход конкретного сервиса; `443` обычно принимает HTTPS, внутреннее приложение может слушать `8000`.
- **HTTP/HTTPS** задают протокол обмена; HTTPS добавляет шифрование и проверку сертификата.
- **Reverse proxy** принимает внешний запрос и маршрутизирует его во внутренний сервис, часто завершая TLS.
- `localhost` и `127.0.0.1` обозначают текущую машину; внутри Compose имя базы обычно `db`, а не `localhost`.
- Сначала наблюдение на каждом участке, затем изменение конфигурации.

## Практический метод

Запишите сетевую карту: домен, ожидаемый IP, публичный порт, proxy, внутренний host/port приложения, API URL, база и место логов. При недоступности проверяйте по порядку: резолвится ли домен; достижим ли сервер; открыт ли `80/443`; отвечает ли proxy; запущено ли приложение; слушает ли `0.0.0.0` внутри контейнера; доступна ли база; куда реально обращается frontend.

Разделяйте симптомы. Нет DNS-ответа — не проблема Python. `502` обычно означает, что proxy не получил корректный ответ upstream. `404` на API требует проверить маршрут/prefix. Frontend открыт, но данные не грузятся — смотрите browser network/console, API URL, CORS, backend и auth. Проверку публичной версии выполняйте с внешнего браузера, не только с сервера.

## Антипаттерны

- Отправлять пользователю `http://localhost:8000` как ссылку.
- Делать вывод «код сломан» по одному сообщению «сайт не открывается».
- Открывать внутренние порты базы или мониторинга наружу вместо настройки сети/proxy.
- Использовать `localhost` между контейнерами Compose.
- Менять DNS, firewall, proxy и код одновременно, теряя причинность.
- Считать HTTPS настроенным, не проверив домен, сертификат и внешний запрос.

## Критерии проверки

- Домен разрешается в ожидаемый IP.
- Сервер доступен, а наружу открыты только необходимые порты.
- Proxy направляет запрос на фактический host/port работающего приложения.
- Приложение слушает адрес, доступный из нужной сети или контейнера.
- Frontend использует правильный публичный API URL, а не локальный адрес автора.
- HTTPS-сертификат действителен; главная страница и API проверены извне.
- Логи proxy, app и db позволяют локализовать участок сбоя без догадок.
