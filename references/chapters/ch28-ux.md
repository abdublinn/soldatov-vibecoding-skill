# UX, минимальный дизайн и здравый интерфейс

## Главная мысль

Минимальный UX — не декоративная полировка, а устранение сомнений пользователя: где он находится, что может сделать, какие данные нужны, что произошло после действия и как исправить ошибку. Для раннего продукта важнее ясный сценарий, читаемая иерархия и полные состояния интерфейса, чем оригинальный визуальный стиль. Вайбкодер принимает UI по наблюдаемому поведению, а AI использует для локальных улучшений, не отдавая ему право бесконтрольно перестраивать продукт.

## Модели и правила

- Экран должен отвечать на четыре вопроса: **что это → что здесь важно → что сделать дальше → что получилось**.
- Визуальная иерархия строится размером, контрастом, расстоянием и порядком, а не множеством цветов и эффектов. Одна главная операция — один заметный primary action.
- Любая работа с данными имеет состояния: loading, empty, success, validation error, server error, disabled/processing. «Идеальный заполненный экран» — лишь один вариант.
- Форма минимизирует усилие: понятные labels, подходящие типы полей, обязательность, примеры формата, сохранение введённого при ошибке, сообщение рядом с причиной.
- Сообщение об ошибке говорит человеческим языком, что произошло и что можно сделать; технические tracebacks остаются в защищённых логах.
- Responsive-проверка обязательна даже для desktop-first MVP: основной сценарий должен быть выполним на узком экране без горизонтальной ловушки.

## Практический метод

1. Выбери один ключевой сценарий и запиши путь пользователя от входа до подтверждённого результата. Удали шаги, не создающие ценность или контроль.
2. Для каждого экрана обозначь заголовок, основной объект, primary action, вторичные действия и обратную связь. Проверь порядок чтения без визуального декора.
3. Составь матрицу состояний для списков, карточек и форм: пусто, загрузка, успех, ошибка, нет доступа, длинные данные, мобильный экран.
4. Проси AI менять конкретный компонент и конкретное состояние. Перед правкой запроси список затрагиваемых файлов; после — просмотри HTML/JS/CSS diff отдельно.
5. Пройди интерфейс клавиатурой, проверь видимый focus, labels, контраст, размеры кликабельных областей и понятность без цвета как единственного сигнала.
6. Проверь реальные крайние данные: длинное имя, пустое описание, неверный формат, повторная отправка, медленный ответ, отказ backend.
7. Проведи короткий пользовательский тест: дай задачу без подсказок, наблюдай места пауз и исправляй сначала препятствия, затем эстетику.

## Антипаттерны

- Начинать с «сделай современно и красиво» без сценария и критерия успешности.
- Создавать несколько равноправных ярких кнопок и скрывать основное действие.
- Использовать placeholder вместо label или показывать ошибку только цветом.
- Очищать форму после неуспешной отправки и заставлять вводить всё заново.
- Игнорировать empty/loading/error, потому что демо заполнено идеальными данными.
- Просить AI полностью переписать CSS/компоненты ради локальной проблемы.
- Считать мобильную версию уменьшенной картинкой desktop без проверки касаний и порядка блоков.

## Критерии проверки

- Незнакомый пользователь понимает назначение экрана и следующий шаг без объяснения.
- Ключевой сценарий завершается с очевидным подтверждением и без лишних развилок.
- Все основные состояния реализованы; ошибки сохраняют ввод и предлагают действие.
- Primary action различим, текст и структура читаются, focus и labels доступны.
- На узком экране нет недоступных элементов и горизонтального скролла в основном сценарии.
- Реальные длинные, пустые и ошибочные данные не ломают макет или логику.
- UI-изменение локально, diff просмотрен, существующие сценарии прошли регрессию.
