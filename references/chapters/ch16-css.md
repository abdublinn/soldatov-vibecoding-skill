# Базовый CSS для вайбкодера

## Главная мысль

CSS управляет вниманием, читаемостью и состояниями, а не просто «красотой». Безопасная AI-правка улучшает один визуальный результат, использует существующую систему классов, не переименовывает JS-hooks и проверяется на нескольких размерах экрана.

## Модели и правила

- **Selector** определяет область действия; слишком общий `button` или `div` может неожиданно изменить весь интерфейс.
- **Box model:** width/content, padding, border, margin объясняют размеры и расстояния; случайные отрицательные отступы маскируют структуру.
- `display`, flex/grid и alignment задают раскладку; правило выбирают по задаче, а не по моде.
- Классы отражают роль (`primary-button`, `status-closed`), а не случайный внешний вид (`blue-box-2`).
- Визуальные состояния success/error/disabled/empty должны быть различимы не только цветом и согласованы с поведением.
- Responsive-проверка — часть каждой заметной правки, даже если полноценная design system не нужна.

## Практический метод

Сначала сформулируйте функциональную цель: «главная кнопка заметна», «статус читается в списке», «форма не слипается на мобильном». Найдите конкретные HTML-классы и все правила, влияющие на них, включая media queries и specificity. Ограничьте prompt: «измени только CSS формы; HTML, JS, id и backend не трогать».

Делайте один визуальный шаг: отступы и ширина формы; затем кнопка; затем статусы. После каждого откройте ключевой экран на широкой и узкой ширине, проверьте длинный текст, пустой список, validation error и disabled action. Если требуется новый class, добавьте его в HTML без изменения selectors, используемых JS. Просмотрите diff на `!important`, inline styles и широкие selectors.

## Антипаттерны

- «Освежить весь дизайн» ради одной проблемы списка или формы.
- Накладывать отрицательные margin и `!important` поверх непонятной структуры.
- Использовать хаотичные inline-style, дублирующие классы и случайные пиксели.
- Менять `id/class`, к которым привязан JavaScript, не проверив связь.
- Полагаться только на цвет для статуса или ошибки.
- Проверять только идеальный desktop screenshot без длинных данных и mobile width.

## Критерии проверки

- Главная цель визуальной правки названа и наблюдаема.
- Selector ограничен нужным компонентом и не меняет соседние элементы.
- Отступы, размеры и состояния следуют небольшой согласованной системе.
- Основное действие, ошибка, success и status визуально различимы и читаемы.
- На узкой ширине нет горизонтальной прокрутки, обрезанного текста и недоступных кнопок.
- HTML/JS-hooks и бизнес-поведение не изменены случайно.
- Diff мал, понятен и не добавляет неуправляемый слой `!important`/inline fixes.
