# Базовый JavaScript для редактирования AI-кода

## Главная мысль

Для безопасной правки AI-frontend нужно видеть цепочку поведения: HTML-элемент → selector → event → чтение данных → `fetch` → response/error → обновление DOM. Не требуется знать весь JavaScript; требуется локализовать сломанное звено и не заменять простой handler новым framework.

## Модели и правила

- `const`/`let` связывают имя со значением; object хранит поля, array — набор сущностей.
- Функция оборачивает одно действие; условие отделяет success/error и допустимый ввод.
- **DOM** — представление HTML; `querySelector` должен совпадать с реальным `id`/`class`, иначе вернёт `null`.
- **Event** связывает действие пользователя с handler; submit обычно требует управляемого предотвращения перезагрузки.
- **`fetch`** отправляет HTTP-запрос; `async/await` управляет ожиданием, но HTTP `4xx/5xx` нужно обрабатывать явно.
- UI-состояние после ответа должно отражать реальность сервера, а не оптимистичную картинку без сохранения.

## Практический метод

При «кнопка не работает» сначала подтвердите загрузку скрипта через browser console/network, затем selector, регистрацию listener и появление события. Для формы выпишите имена полей, payload, URL/method, ожидаемый status/body и DOM-функцию отображения. Сопоставьте их с HTML и backend API.

Точечную правку формулируйте узко: «после успешного создания вызвать `form.reset()`; не менять API, HTML и CSS». После изменения проверьте: корректный submit; пустой ввод; server error; отсутствие console errors; запрос на правильный адрес; UI обновляется только после подтверждённого результата. Если ошибка между слоями, передавайте AI вместе HTML, JS и API-договор, а не один fragment.

## Антипаттерны

- Переписать один handler на React/Vue из-за непонимания `addEventListener`.
- Переименовать HTML `id`/`name`, не обновив selectors и backend field.
- Считать `fetch` успешным только потому, что Promise завершился; игнорировать `response.ok` и тело ошибки.
- Показывать «сохранено» до подтверждения сервера.
- Ловить ошибку пустым `catch`, не показывая пользователю и не логируя контекст.
- Смешать бизнес-правку, redesign и смену API в одном diff.

## Критерии проверки

- JS-файл фактически подключён и выполняется.
- Selectors находят ожидаемые элементы; listener срабатывает один раз.
- Payload использует поля и типы, которые ждёт backend.
- URL, method, headers и обработка ответа соответствуют API.
- Success, validation error и server/network error дают различимые состояния.
- После действия DOM показывает подтверждённые данные, форма и список ведут себя ожидаемо.
- Browser console/network не содержат новых ошибок; старый сценарий не сломан.
