# Как читать проект, написанный AI

## Главная мысль

Незнакомый AI-проект читают не как роман от первого файла до последнего, а как систему: команда запуска → entry point → routes/pages → templates/components → JS/CSS → models/data → config/env. Сначала карта и цепочка пользовательского действия, только затем правка.

## Модели и правила

- **Entry point** показывает, как начинается выполнение: файл, модуль или script в manifest/package config.
- **Маршрут/страница** связывает URL или событие с handler и template/component.
- **Модель/сущность** определяет данные; migration/schema показывает, как структура живёт в базе.
- **Config/env** отделяет окружение от логики; README — гипотеза о запуске, которую нужно проверить.
- **Цепочка влияния:** действие пользователя → UI → handler/API → validation → data → response → отображение.
- Файлы dependencies, lockfiles, migrations, CI/deploy и secrets нельзя менять наугад до понимания назначения.

## Практический метод

Сначала прочитайте дерево проекта, README и файлы запуска. Не редактируя, найдите: фактическую команду; entry point; route главного сценария; форму; список/карточку; CSS/JS; модель; database config; env; тесты. Составьте таблицу «элемент → файл → роль → как проверить → неизвестное».

Для конкретной правки сформулируйте наблюдаемое поведение, затем пройдите цепочку по коду. Чтобы добавить phone, нужны не только поле формы, но и payload, validation, model/migration, persistence, response и отображение. Просите AI ссылаться на фактические файлы и отмечать «нужно проверить», если связь не найдена. Измените минимальное место, запустите основной и затронутый сценарии.

## Антипаттерны

- Искать текст по проекту, менять первое совпадение и не проверять, рендерится ли этот файл.
- Просить «разберись в проекте» без требуемой карты и ссылок на файлы.
- Верить README или AI-объяснению без фактического запуска.
- Добавить видимое поле, не проведя его через data path.
- Менять migrations, lockfile, deployment config или auth «для порядка».
- Полностью перегенерировать проект, потому что одна цепочка пока непонятна.

## Критерии проверки

- Фактическая команда запуска воспроизведена, entry point найден.
- Основные routes/pages сопоставлены с templates/components и handlers.
- Найдены model/schema, storage и config/env главной сущности.
- Для нужного поведения записана полная цепочка файлов и данных.
- Неизвестное явно отделено от подтверждённого ссылкой на код.
- До правки известны защищённые файлы, old scenario и acceptance check.
- После малого diff проект запускается, новая функция реальна, а старый главный сценарий не сломан.
