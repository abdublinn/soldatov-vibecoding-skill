# Базовый Python для редактирования AI-кода

## Главная мысль

Вайбкодеру не нужен полный курс Python, чтобы контролировать простой AI-backend. Нужен навык прочитать путь данных: imports и config → route/function → входной `dict`/model → validation → изменение данных → response/error. Безопасная правка мала, локализована и имеет один наблюдаемый сценарий.

## Модели и правила

- **Переменная и тип** объясняют, какое значение ожидается; `dict` хранит поля сущности, `list` — набор записей.
- **Условие** защищает правило: обязательность, допустимый статус, отсутствие записи. **Цикл** обходит коллекцию, но не заменяет запрос к базе.
- **Функция** имеет вход, преобразование/эффект и return; имя должно описывать одно действие.
- **Import** показывает внешнюю зависимость или связь с модулем проекта; ошибка импорта диагностируется через окружение и файл зависимостей.
- **Handler/route** принимает request, валидирует, вызывает бизнес-логику и формирует response; эти стадии полезно видеть отдельно.
- Отступы — синтаксис и структура; точечная правка не должна «заодно» менять стиль всего файла.

## Практический метод

Откройте не случайный `.py`, а файл, связанный с нужным маршрутом. Сначала попросите AI составить карту функции: входные данные, обязательные поля, проверки, side effects, return и вызывающие места — со ссылками на код. Для добавления `description` найдите модель/структуру, validation, создание записи, сериализацию/response и тест/ручной сценарий.

Меняйте одну функцию или один проход данных. После правки запустите существующие тесты либо приложение; отправьте корректный и пустой ввод; проверьте HTTP-ответ, сохранённое значение и лог. При `KeyError` сначала найдите прямой доступ `data["status"]` и реальную форму входа, а не переписывайте backend. Новую зависимость добавляйте в файл зависимостей и пересобирайте окружение.

## Антипаттерны

- Переписать весь backend, потому что непонятна одна функция.
- Добавить поле только в Python-словарь, забыв форму, validation, persistence и output.
- «Исправить» ошибку широким `except Exception: pass`, скрыв симптом и traceback.
- Менять формат API-ответа или имена маршрутов в локальном bugfix без необходимости.
- Устанавливать пакет вручную внутри контейнера и не фиксировать зависимость.
- Принимать in-memory `list` за постоянное хранилище после перезапуска.

## Критерии проверки

- Можно назвать функцию, которую меняем, её вход и return.
- Известно, где route получает поле, где оно проверяется и где сохраняется.
- Отступы и imports корректны; приложение/модуль загружается без syntax/import errors.
- Корректный ввод проходит, пустой/ошибочный даёт ожидаемую понятную ошибку.
- Ответ и сохранённые данные совпадают; после нужного перезапуска состояние ведёт себя согласно архитектуре.
- Diff ограничен нужными файлами и не меняет соседнее публичное поведение.
- Ручной сценарий или тест зафиксирован до признания правки рабочей.
