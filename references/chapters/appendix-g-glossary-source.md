# Словарь терминов

## Главная мысль

Термины полезны как карта решений, а не как экзаменационный словарь. В AI-разработке одинаковые слова часто скрывают разные объекты: prototype и production, image и container, authentication и authorization, log и metric. Перед планом или исправлением уточняй рабочее значение термина в текущем проекте и связывай его с наблюдаемым артефактом. Если команда и AI используют разные определения, ошибка проявится позже как неверная граница MVP, потерянные данные или опасный deploy.

## Модели и правила

- **Продуктовый слой:** идея — предположение; продукт — ценность плюс пользовательский сценарий и механизм; MVP — минимальная версия для проверки ценности; prototype/demo — доказательство концепции, не обязательно эксплуатационно готовое.
- **Требования:** functional requirement описывает поведение; non-functional — качество/ограничение; acceptance criterion — наблюдаемый способ принять результат; Definition of Done — общий gate готовности.
- **Архитектура:** frontend взаимодействует с пользователем; backend реализует серверные правила; database хранит состояние; API задаёт контракт; component/deployment diagrams показывают части и размещение.
- **Данные:** entity — значимый объект; field — его свойство; CRUD — create/read/update/delete; migration — контролируемое изменение схемы; backup — копия для восстановления.
- **Версии:** repository хранит историю; commit — точка изменения; branch — линия работы; diff — отличие состояний; rollback — возврат к известной версии.
- **Эксплуатация:** image — неизменяемый шаблон; container — экземпляр; service — роль; volume — постоянные данные; log/metric/health/alert — разные сигналы состояния.

## Практический метод

В начале задачи выпиши неоднозначные существительные и преврати их в объекты/критерии. «Сайт готов» уточни до адреса, роли, сценария, данных, доступности и проверки. «База» уточни до технологии, схемы, экземпляра, среды и backup. «Авторизация» раздели на login и проверку разрешения. «Развернуть» разложи на version, environment, config, migration, process, network, HTTPS, smoke и rollback.

При разговоре с AI добавляй локальный словарь: названия services, entities, статусов и ролей точно как в коде/документах. В review сверяй термин с артефактом: `volume` виден в Compose, acceptance — в тесте/сценарии, API contract — в route/schema. Если слово не влияет на решение, не расширяй глоссарий. Если влияет — зафиксируй короткое определение и ссылку на source of truth.

## Антипаттерны

- Называть демо «готовым продуктом» без требований эксплуатации и безопасности.
- Путать authentication с authorization и полагаться на скрытый UI.
- Путать image/container или container/volume, считая пересоздание безопасным для данных.
- Использовать «сервер», «хост», «домен» и «приложение» как взаимозаменяемые объекты.
- Считать log, metric и alert одним видом наблюдаемости.
- Просить AI «обновить базу» без указания схемы, данных, среды и отката.
- Создавать энциклопедию терминов без связи с файлами, командами и решениями проекта.

## Критерии проверки

- Продукт, MVP, prototype и production различены по цели и критериям готовности.
- Требование связано с acceptance, а Definition of Done — с полным gate этапа.
- Компоненты frontend/backend/database/API имеют явные границы и потоки.
- Entity/field/status/migration/backup названы однозначно для конкретной среды.
- Git-термины соответствуют текущему состоянию repository; rollback не смешан с удалением истории.
- Docker service/container/image/volume используются в командах в правильном смысле.
- Термины наблюдаемости и безопасности приводят к отдельным проверкам и владельцам.
