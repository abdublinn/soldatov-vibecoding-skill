# Базовый HTML для вайбкодера

## Главная мысль

HTML — каркас интерфейса и договор между пользователем, JavaScript и backend. Безопасная правка сохраняет вложенность, семантику, `id`, `name`, типы кнопок и доступность; новое поле становится функцией только после прохождения всей цепочки до validation, persistence и отображения.

## Модели и правила

- `head` содержит метаданные и подключения, `body` — видимую структуру.
- Контейнеры (`main`, `section`, `form`, `table`) группируют смысл, а не просто создают слои `div`.
- `id` часто является уникальной точкой для JS; `class` связывает элемент со стилем; `name` определяет имя отправляемого поля.
- Кнопка отправки формы должна иметь понятный `type="submit"`; служебная кнопка — явный `type="button"`.
- `label` связывает подпись и поле; семантика и человеческий текст важнее декоративной сложности.
- Изменение разметки проверяется вместе с подключёнными CSS/JS и ожидаемыми backend-полями.

## Практический метод

Перед правкой составьте карту страницы: крупные секции, формы, элементы, используемые JS, и поля, уходящие на сервер. Найдите реальный template/component, который рендерит маршрут, а не первый файл с похожим текстом. Для добавления `priority` укажите значение `name`, допустимые options, обязательность и человеческую подпись; затем найдите чтение поля в JS/backend, validation, сохранение и вывод в карточке.

Попросите AI менять только нужный template и не переименовывать существующие `id/name`. После правки откройте реальную страницу, отправьте форму, проверьте selector-ы, payload и результат после обновления. Комментарий оставляйте только там, где неочевидная связь с JS или backend защищает от случайного переименования.

## Антипаттерны

- «Переделай весь шаблон, чтобы было красивее» без списка защищённых связей.
- Поменять `name="title"` на `ticketTitle`, не обновив все слои.
- Добавить поле только визуально и назвать функцию готовой.
- Использовать один и тот же `id` несколько раз или кнопку без явного типа.
- Ломать вложенность формы/таблицы, принимая визуальный preview за достаточную проверку.
- Встраивать сложные inline-style/inline-script вместо понятных подключённых файлов.

## Критерии проверки

- Изменён именно template/component, который рендерит нужный маршрут.
- Теги корректно вложены; формы, labels и buttons семантически связаны.
- Существующие `id`, `name`, class и JS-selectors сохранены либо согласованно обновлены.
- Новое поле входит в payload, проверяется backend и сохраняется, если это заявленная функция.
- Пустое, успешное и ошибочное состояния видны пользователю.
- Страница открывается без console errors и остаётся пригодной на узкой ширине.
- Diff не затрагивает unrelated templates или бизнес-логику.
